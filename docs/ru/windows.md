# Windows

[English](../windows.md) | **Русский** · [К README](../../README.ru.md)

SocketTrail для Windows выходит в двух сборках с одним и тем же `sockettrail.exe`:

| Сборка | Файл |
|---|---|
| Установщик | `SocketTrail-<версия>-windows-x64-setup.exe` |
| Портативная | `SocketTrail-<версия>-windows-x64-portable.zip` |

Exe собран со статическим CRT и зависит только от системных DLL. Windows 10 и 11, x64.

## Установка

Установщик ставит программу в `C:\Program Files\SocketTrail` для всех пользователей
или, если выбрать **Установить только для меня**, в `%LOCALAPPDATA%\Programs\SocketTrail`
без прав администратора. Он добавляет ярлык в меню «Пуск», по желанию ярлык на рабочем
столе и запись в **Параметры** -> **Приложения** -> **Установленные приложения**. Новая
версия ставится поверх прежней, запущенный SocketTrail перед этим закрывается.
Удаление убирает программу и сохраняет дампы, кеш и настройки, см.
[Где лежат данные](#где-лежат-данные).

Тихая установка: `SocketTrail-<версия>-windows-x64-setup.exe /VERYSILENT`, для установки
только для текущего пользователя добавьте `/CURRENTUSER`.

Портативный zip устанавливать не нужно: распакуйте его в любую папку.

## Запуск

1. Запустите **SocketTrail** из меню «Пуск» или `sockettrail.exe` из папки, куда
   распакован архив.
2. Откроется окно Microsoft Edge или Chrome с интерфейсом. Консоль CMD/PowerShell не открывается.
   Закрытие окна приложения завершает работу, незаконченный дамп дописывается.
3. Exe пока не подписан, поэтому SmartScreen может показать "Система Windows защитила
   ваш компьютер": **Подробнее** -> **Выполнить в любом случае**. Контрольные суммы и
   аттестация сборки лежат на странице релиза, см.
   [Проверка загрузки](#проверка-загрузки).

## Два режима

| | Без прав администратора | От администратора |
|---|---|---|
| Процессы и соединения | да | да |
| Домены | из DNS-кеша системы | из DNS-ответов и SNI из TLS и QUIC, включая браузеры |
| Трафик по соединениям | нет | да |
| Цели UDP | нет | да |
| Соединения короче 250 мс | нет | да |
| Дампы `.pcapng` | нет | да, через PktMon |
| Дополнительные программы | не нужны | не нужны |

**Без прав администратора** домены берутся из DNS-кеша Windows, того же, что
показывает `ipconfig /displaydns`. Так видны игры, Steam, системные службы и
большинство программ, но не Chrome и Edge: у браузеров свой DNS-клиент. Кеш
опрашивается каждые 3 секунды, поэтому домены появляются в течение нескольких секунд.
Соединение, открытое до запуска SocketTrail, получит имя, только пока его запись еще
лежит в кеше.

**От администратора** SocketTrail ведет собственный захват пакетов. Встроенный в
Windows драйвер PktMon (Windows 10 версии 2004 и новее, Windows 11) запускается
штатной утилитой `pktmon`, а кадры читаются из отдельной ETW-сессии. Ни Wireshark, ни
Npcap не нужны. Нажмите **Перезапустить от администратора** в окне или запустите exe
через **Запуск от имени администратора**.

SocketTrail использует только собственный движок захвата PktMon/ETW.
Wireshark, Npcap и `dumpcap.exe` не запускаются, даже если установлены.
Без прав администратора захват пакетов и запись дампов недоступны.

Метка в шапке окна показывает режим: **Полный режим** или **Базовый режим**. Для анализа
и дампов запускайте от администратора: так видна полная картина. Режим без прав годится
для беглого просмотра того, какие программы держат соединения.

## Отличия от Linux

- В таблице UDP у Windows нет удаленного адреса, поэтому цели UDP берутся только из
  разбора пакетов. Владелец определяется по локальному адресу, порту и семейству
  IP; время создания сокета не дает повторно использованному порту забрать старый
  трафик.
- PktMon захватывает со всех сетевых адаптеров. Ключ `-i` на Windows не действует.
- Пока SocketTrail работает, `pktmon` занят им: запуск другого захвата pktmon
  останавливает наш.
- На некоторых системах поле состояния в таблице TCP смещено относительно строк:
  `netstat -ano` показывает `LISTENING` с адресом сервера, а состояния многих строк
  меняются разом, при этом адреса и PID остаются верными. SocketTrail распознает это по
  невозможным строкам, хранит последнее достоверное состояние соединения и показывает
  `OPEN`, пока ни одного не прочитано. На владельца соединения это не влияет.
- Определять Proton не нужно, плашка PROTON и вкладка **Proton** не показываются.

## VPN и TUN-адаптеры

С TUN-адаптером один и тот же трафик виден дважды: внутри туннеля, где программы
обращаются к своим серверам с адреса туннеля, и снаружи, где компьютер обращается к
серверу VPN с физического адаптера. PktMon захватывает оба слоя. Программе принадлежат
только внутренние соединения, поэтому дамп процесса оставляет их и не включает внешний
туннель. В дампе всего компьютера внешний туннель — это один большой поток к серверу
VPN, и при разбиении он попадает в отдельную часть.

## Где лежат данные

| Данные | Путь |
|---|---|
| Дампы | `%USERPROFILE%\SocketTrail` |
| Кеш имен, язык, профиль окна | `%LOCALAPPDATA%\SocketTrail` |

Журнал: `%LOCALAPPDATA%\SocketTrail\sockettrail.log`.
Обычный запуск и перезапуск от администратора не создают консоль.
При явном запуске с `--no-open` из терминала вывод идет в существующий терминал;
`--help` выводит справку туда же, либо в отдельный диалог, если терминала нет.

## Проверка загрузки

У каждого релиза есть файл `SHA256SUMS` и аттестация сборки GitHub, которая
связывает каждый файл с запуском workflow, собравшим его:

```powershell
$file = Get-Item .\SocketTrail-*-windows-x64-setup.exe   # или -portable.zip
Get-FileHash $file -Algorithm SHA256
gh attestation verify $file --repo mazixs/SocketTrail
```

Сравните хеш со строкой в `SHA256SUMS`. Для последней команды нужен
[GitHub CLI](https://cli.github.com/). `.deb` проверяется так же, через `sha256sum` и
`gh attestation verify`.
