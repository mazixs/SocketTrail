# Windows

[English](../windows.md) | **Русский** · [К README](../../README.ru.md)

SocketTrail для Windows - это портативный zip: `sockettrail.exe`, `README.txt` и
`LICENSE.txt`. Устанавливать ничего не нужно. Exe собран со статическим CRT и зависит
только от системных DLL. Windows 10 и 11, x64.

## Запуск

1. Распакуйте архив в любую папку и запустите `sockettrail.exe`.
2. Откроется окно Microsoft Edge или Chrome с интерфейсом. Окно консоли - это журнал
   программы: закрытие любого из окон завершает работу, незаконченный дамп
   дописывается.
3. Exe пока не подписан, поэтому SmartScreen может показать "Система Windows защитила
   ваш компьютер": **Подробнее** -> **Выполнить в любом случае**. Контрольные суммы и
   аттестация сборки лежат на странице релиза, см.
   [Проверка загрузки](#проверка-загрузки).

## Два режима

| | Без прав администратора | От администратора |
|---|---|---|
| Процессы и соединения | да | да |
| Домены | из DNS-кеша системы | из DNS-ответов и TLS SNI, включая браузеры |
| Трафик по соединениям | нет | да |
| Дампы `.pcapng` | только через `dumpcap` из Wireshark, если он установлен | да, через PktMon |
| Дополнительные программы | не нужны | не нужны |

**Без прав администратора** домены берутся из DNS-кеша Windows, того же, что
показывает `ipconfig /displaydns`. Так видны игры, Steam, системные службы и
большинство программ, но не Chrome и Edge: у браузеров свой DNS-клиент. Кеш
опрашивается каждые 3 секунды, поэтому домены появляются в течение нескольких секунд.
Соединение, открытое до запуска SocketTrail, получит имя, только пока его запись еще
лежит в кеше.

**От администратора** SocketTrail ведет собственный захват пакетов. Встроенный в
Windows драйвер PktMon (Windows 10 версии 2004 и новее, Windows 11) запускается
штатной утилитой `pktmon`, а кадры читаются из отдельной ETW-сессии. Ни Wireshark, ни
Npcap не нужны. Нажмите **Перезапустить от администратора** в окне или запустите exe
через **Запуск от имени администратора**.

Если установлен Wireshark с Npcap, SocketTrail без прав администратора использует его
`dumpcap.exe` для захвата и дампов.

## Отличия от Linux

- В таблице UDP у Windows нет удаленного адреса, поэтому цели UDP берутся только из
  разбора пакетов, а владелец определяется по локальному порту.
- PktMon захватывает со всех сетевых адаптеров. Ключ `-i` действует только на
  запасной вариант через `dumpcap`.
- Пока SocketTrail работает, `pktmon` занят им: запуск другого захвата pktmon
  останавливает наш.
- Определять Proton не нужно, плашка PROTON не показывается.

## Где лежат данные

| Данные | Путь |
|---|---|
| Дампы | `%USERPROFILE%\SocketTrail` |
| Кеш имен, язык, профиль окна | `%LOCALAPPDATA%\SocketTrail` |

## Проверка загрузки

У каждого релиза есть файл `SHA256SUMS` и аттестация сборки GitHub, которая
связывает zip с запуском workflow, собравшим его:

```powershell
$zip = Get-Item .\SocketTrail-*-windows-x64.zip
Get-FileHash $zip -Algorithm SHA256
gh attestation verify $zip --repo mazixs/SocketTrail
```

Сравните хеш со строкой в `SHA256SUMS`. Для последней команды нужен
[GitHub CLI](https://cli.github.com/). `.deb` проверяется так же, через `sha256sum` и
`gh attestation verify`.
