# Repository Guidelines

## Структура проекта

SocketTrail - монитор сетевых соединений для Linux и Windows на Rust 2024; минимальная версия Rust - 1.89. `src/main.rs` содержит запуск и HTTP API, остальные модули отвечают за захват, разрешение доменов, историю и экспорт. Платформенные реализации находятся в `src/procs/`, `src/sockets/` и `src/capture/`. Windows использует только собственный движок PktMon/ETW, без Wireshark, Npcap и dumpcap. Интерфейс с HTML, CSS и JavaScript расположен в `ui/index.html`, без отдельной frontend-сборки. `assets/` содержит иконки, манифест и службу; `packaging/` - сборку пакетов и smoke-проверку. Документация находится в `docs/`, переводы - в `docs/ru/`, тестовые пакеты - в `src/testdata/`.

## Сборка и разработка

- `make run` или `./run.sh --lang ru --port 8790` - собрать при необходимости и запустить приложение.
- `make build` - собрать release-бинарник в `target/release/`.
- `make check` - проверить доступность захвата через `dumpcap` без root.
- `cargo fmt --check` - проверить форматирование; `cargo fmt` - исправить его.
- `cargo clippy --all-targets` и `cargo test` - проверить код и выполнить тесты.
- `packaging/smoke.sh target/release/sockettrail` - после сборки проверить запуск и HTTP API.
- `make deb` и `make win` - создать Linux-пакет и Windows-архив.

Для Windows на Linux нужны mingw-w64, установленная цель `x86_64-pc-windows-gnu` и WineHQ 10+. Выполняйте `cargo clippy --all-targets --target x86_64-pc-windows-gnu` и `cargo test --target x86_64-pc-windows-gnu`.

## Стиль и локализация

Используйте rustfmt, отступы Rust в четыре пробела, `snake_case` для функций и модулей, `PascalCase` для типов, `SCREAMING_SNAKE_CASE` для констант. Сохраняйте существующий компактный стиль интерфейса. CI запрещает предупреждения через `RUSTFLAGS="-D warnings"`. Новые строки добавляйте на английском и русском: через `t!`/`text!` в Rust и словарь `RU` в интерфейсе. Обновляйте обе версии затронутой документации.

## Тестирование

Добавляйте регрессионные тесты рядом с кодом в `#[cfg(test)] mod tests`, используя `#[test]` и описательные имена `snake_case`. Числовой порог покрытия не задан. Проверяйте измененное поведение и граничные случаи парсинга. На настоящей Windows запускайте `cargo test -- --include-ignored` для сетевого DNS-теста. Smoke-проверка API не подтверждает корректность захвата трафика; проверяйте его отдельно при изменении соответствующих модулей.

## Коммиты и pull request

Последние коммиты используют английские сообщения вида `Linux: ...`, `CI: ...`, `Release vX.Y.Z`; придерживайтесь этого формата. Перед коммитом проверяйте состав изменений. В PR указывайте проблему, итоговое поведение, связанные issues при наличии и выполненные проверки. Для изменений интерфейса прикладывайте снимки обеих тем без личных данных.

## Безопасность

Сохраняйте привязку сервера к `127.0.0.1` и проверки Host/Origin. Не коммитьте дампы, пользовательскую историю, кеши, отчеты и содержимое `target/`.

Документация, примеры, скриншоты и описания релизов должны быть обезличены. Из данных автора допускаются только никнейм и почта. Используйте демонстрационные процессы, домены `example.com`, адреса для документации и нейтральные пути; не публикуйте реальные сессии и метаданные компьютера.
